# wheal —— 风团 2.5D 高度图分析

过敏原风团（wheal）隆起量的深度测量可行性调研。属于
[issue #1](https://github.com/transmit-bug/orbbec-openni2-capture/issues/1) 的实现。

**这不是产品，是 spike。** 目标是产出一组带测量的结论：在给定工作距离和帧数下，
这套硬件能分辨多小的隆起、误差多大、在什么条件下失效。结论有可能是"不适用"。

## 与 C++ 侧的分工

```
C++ (src/, 现有)          Python (本目录)
  采集 + 录制       →        分析 + 报告
  frame_0000.pgm             analyze()
  metadata.json
```

语言边界正好落在 **Seam 2（帧来源）** 上：C++ 把序列录成 16-bit PGM 落盘，
Python 从磁盘读。没有 pybind11、没有 FFI、没有构建耦合——采集继续留在 C++，
因为 OpenNI2 设备访问、定制驱动、旧固件的 `ASTRA_DEPTH_FORMAT=ps` 变通都在那边。

## 两个接缝

| 接缝 | 位置 | 如何测试 |
|---|---|---|
| **Seam 1** — 纯分析函数 | `wheal.analyze.analyze()` | 合成数据：已知平面 + 已知高斯凸起 + 可控噪声。无硬件、确定性 |
| **Seam 2** — 帧来源 | `wheal.frames.FrameSource` | PGM 序列 fixture。无相机机器上必须通过 |

内部两步（稳健基准面 → 残差与指标）刻意保持私有——接缝越少越好。

## 模块分层：通用几何 ∥ 风团领域

```
stats.py        叶子：MAD→sigma 常量（无包内依赖）
accumulate.py   多帧累积：降噪 + 填洞              ← 通用，不认识风团
geometry.py     反投影 / 三角化 / 法向 / PLY      ← 通用，不认识风团
───────────────── 以上三层不 import 以下任何模块 ─────────────────
baseline.py     稳健基准面拟合
metrics.py      风团参数与指标
analyze.py      累积 + 基准面 = 风团测量
```

**这里没有“场景”这个概念。** `geometry` 不拟合基准面，因为深度值本身就是模型；
`analyze` 拟合基准面，因为皮肤是已知的参考面。两者不是并列的两条流水线，而是
**包含关系**：`analyze` = `accumulate` + 一个基准面。对着平墙跑 `analyze`，
`fit_baseline` 会把墙拟合成基准面并报出墙的粗糙度——它不需要知道那是墙。

真正区分两者的是**有没有一个可以拟合掉的参考面**，不是“拍的是什么”。

这条分界曾经是破的：``geometry``（当时叫 ``scene``）从 ``analyze`` import
``accumulate``、从 ``metrics`` import ``AnalyzeParams``，于是“通用 2.5D 建模”
只是口号——任何复用都得先把风团研究模块拖进来。现在由
`tests/test_layering.py` 用 AST 检查允许集合（**精确匹配**，新增依赖必须改表），
故意的回归验证过会被抓到。

## 怎么看这些产物（以及为什么"打开都是黑的"）

三个产物各有各的黑法，原因完全不同，而且**都是静默的**——文件大小正常、退出码为 0、
没有任何报错，只是屏幕上什么都没有。分不清就会去查错的环节。

| 产物 | 为什么黑 | 怎么开 |
|---|---|---|
| `frame_*.pgm`（用普通看图程序） | 深度值是**毫米原值**（460..630），而 PGM 声明 `maxval=65535`。看图程序只显示高字节，`460 >> 8 == 1` → 全图落在 0..2/255 | `uv run wheal preview ../output/seq_indoor --out ../output/preview --fuse` |
| `points.ply` / `mesh.ply`（用带光照的渲染器，**旧版导出**） | 没有顶点色也没有法向。渲染器只能拿默认材质（黑）画它，且单视角 2.5D 面的法向朝**远离相机**的一侧，看到的是背面 | 现在导出默认带颜色+法向，且法向已翻向相机 |
| `mesh.ply`（**Blender**） | Blender 5.2.2 的**二进制 PLY 读取器本身是错的**，见下 | 现在导出默认就是 ascii，直接能开 |

### ⚠️ Blender 5.2.2 的二进制 PLY 读取器是错的

实测（Blender 5.2.2 LTS 的 `wm.ply_import`，下面每种形状都独立复现过）：只要
vertex 元素里除了 `x y z` 还有**任何**别的属性，读到的位置就是错的。

| vertex 元素里的属性 | Blender 读到的位置 |
|---|---|
| `x y z` | 正确（唯一正确的情形） |
| `x y z foo` | `y z foo`——整体错位一个属性 |
| `x y z nx ny nz` | 读到法向（单位向量，于是包围盒变成 ±1） |
| `x y z red..blue` | 垃圾 float，量级 `1e38`（等于未初始化的内存） |
| `x y z nx ny nz red..blue` | 垃圾 float |

不是"不认颜色"，是**整个二进制路径的位置解析都错了**，碰巧只在"顶点元素恰好只有
3 个 float 属性"时看不出来。ASCII 路径完全正常，`float` 或 `uchar` 颜色都行，
所以 `scene` 默认写 ascii。二进制保留在 `--ply-format binary`（体积约 1/3），
适合当存档；我们自己的解析器读二进制是正确的（逐字节验证过）。

见 `tests/test_geometry.py::TestPlyReaderInterop`——那里钉住了这条结论，
以免有人"顺手统一一下格式"把 ascii 拿掉。

### 推荐的查看器

```bash
# 深度图（最常看的就是这个）
uv run wheal preview ../output/seq_indoor --out ../output/preview --fuse
#   → preview/sequence.png   缩略图网格（共同显示区间，能一眼看出空洞模式）
#   → preview/frame_0000.png 首帧大图（带色标）
#   → preview/fused.png      累积后的深度图 + fused.pgm（16-bit，可继续下游）

# 三维（下面是重点：裸导入是黑的，这个脚本打开就能看）
blender --factory-startup --python ../scripts/view_in_blender.py -- \
    ../output/scene_indoor/mesh.ply
```

**为什么不直接 `blender mesh.ply`。** 裸 `wm.ply_import` 得到的是一个**黑色**的
物体：导入的网格没有材质，而默认引擎是 EEVEE——没有材质就是黑的。“没设对”和
“文件坏了”在屏幕上长得一模一样，分不出来。`scripts/view_in_blender.py` 把三件
必须做的事一次做掉：

1. 着色模式切 `Workbench` + `VERTEX`（不需要灯光，直接读顶点色属性）；
2. 材质里接上 ``Col`` 属性 → Principled BSDF，这样按 `F12` 或切 EEVEE 也有颜色；
3. 视口**直接切到相机视角**，并把相机摆在能看出几何的斜角上。

第 3 条不是锦上添花。第一版脚本手算了 ``view_location`` / ``view_distance``，
结果打开后镜头落在几何**内部**，看到的是一片巨大的绿色尖刺（其实是行相关伪影
被放大了几百倍），模型看起来像坏掉了。相机视角没有这个歧义：位置和朝向都是
真实几何量。

脚本**默认不写任何文件**。它曾经在 PLY 旁边存一份 `.blend`，于是每跑一次就多出
一个 16 MB 的 `.blend` 加一个 16 MB 的 `.blend1` 自动备份——而两者都能从 PLY
重新生成。要存盘请显式加 `--save`。

进去以后：鼠标中键旋转、滚轮缩放（会自动回到自由视角）；`Numpad 0` 切回相机视角。

## ⚠️ 未解决：上半幅的确定性行相关伪影

**这是当前最严重的问题，也是下一步该处理的。** 它比噪声底和量化台阶都优先——
噪声底只影响“能分辨多小”，这个伪影直接影响“测出来的高度是不是真的”。

实测（`output/seq_indoor`，120 帧）：

| 区域 | 相邻行差 p90 | 相邻列差 p90 | 不对称 |
|---|---|---|---|
| 行 300–480（下半幅） | 1.47 mm | 0.53 mm | 正常 |
| 行 0–300（上半幅） | **41.12 mm** | 1.62 mm | **25×** |

判定为伪影而不是真实几何的依据（不是猜的）：

1. **整行平移判据。** 抽查跳变最大的行对，跳变中位 26–39 mm 而离散度仅 4–11 mm
   ——整行**所有列同时**偏移。真实几何做不到这一点，它必然是空间局部化的。
2. **可复现。** 同一段录制的前后半段，行偏移模式相关系数 **0.87**——确定性的，
   不是噪声。这意味着**时间累积永远消不掉它**，加帧数没有帮助。
3. **最大行偏移量 120 mm**，而相邻行偏移量差的中位仅 1.43 mm——是整行跳，
   不是逐像素抖。
4. **肉眼可见。** 在 Blender 里看网格，上半幅呈现为**一层一层的台阶/叠层**，
   而不是连续的曲面。这是最直观的一条：它把“整行平移”直接画成了台阶。

### 它与噪声统计的呼应

这套伪影解释了累积降噪为什么远达不到 1/√N：

| N | 实测噪声 | 独立噪声应为 | 比值 |
|---|---|---|---|
| 4 | 17.19 mm | 14.78 | 1.16 |
| 16 | 11.57 mm | 7.39 | 1.57 |
| 60 | 7.58 mm | 3.82 | 1.99 |

时间自相关 ρ≈0.04 看似独立，但 `std / (MAD×1.4826) = 1.91`、p99 偏差达 std 的
4.2 倍——**重尾**。行偏移是重尾的确定性来源：它既不是高斯噪声（所以均值降不下去），
也不随帧变化（所以累积无效）。这也直接推翻了 issue #1 里基于规格书
“1–2 mm @ 1 m”的乐观估计。

### 领先假设：驱动的 S2D 标定参数

`third_party/bugparty-.../docs/s2d-calibration.md` 里写着：PrimeSense 原版 S2D 公式
假设的参数对 Astra Pro **是错的**，用错参数会让深度值偏差数百毫米。而
`depth = focal·BL / (fittingCoeff - shift)`，深度越大对 shift 误差越敏感
（灵敏度 ∝ depth²）——与**伪影集中在上半幅 / 远区**吻合。

驱动里带着 `tools/s2d_calibrate.cpp` 和一套用官方驱动做真值的配对帧标定方法。

### 下一步：一分钟就能定性的实验

对着约 1 m 处**一面平墙**录一段：

- 行带纹照样出现 → 确认是驱动 / S2D 问题，去跑配对帧标定；
- 行带纹消失 → 是低视差区的场景相关匹配失败，靠限制有效量程解决。

**为什么必须请你确认，而不是代码判断。** 代码分不出“伪影”和“真有横向结构”：
对着平墙出现行带纹是传感器缺陷，对着百叶窗出现行带纹是真几何。

（场景相关的一点旁证：累积深度图的下半幅是一条光滑的深度梯度，符合平面；
上半幅是横向毛刺。但“符合平面”不等于“是平面”，仍需现场确认。）

## 单位约定

- 深度：**毫米（mm）**，`uint16`，`0` 与 `65535` 表示无效。全程不做米制转换。
- 高度图：相对拟合基准面的 **Z 方向残差**，单位 mm，`float64`。
  **符号约定 `height = baseline - depth`，正值表示隆起**（风团朝相机凸起）。
  搞反了风团会变成凹坑，而所有统计量仍然"看起来正常"。
- 横向尺度：**默认未知**。隆起高度是纯 Z 量，不需要内参；但面积/体积需要
  横向 mm/px 换算，只有显式提供 `lateral_scale_mm_per_px` 时才给出，
  否则为 `None`——缺失时不编造数字。

## ⚠️ 关键发现：1 mm 量化台阶与时间累积方式

传感器输出**整数毫米**（`PIXEL_FORMAT_DEPTH_1_MM`），而风团高度是 **0.5–1.5 mm**。
量化台阶与待测量同量级，这直接决定了时间累积该怎么做：

| 方式 | 行为 | 实测（真实隆起 0.797 mm，N=64，σ=0.5 mm） |
|---|---|---|
| `median` | **无法突破量化台阶** —— 量化值的中值仍是量化值 | 报 **1.000 mm**，锁在台阶上；噪声底假性归零 |
| `mean` | 能恢复亚量子精度（靠噪声抖动跨越量化边界），但被稀疏离群值污染 | 25% 帧带 +50 mm 离群值时崩到 **8.47 mm** |
| `trimmed_mean`（默认） | 先按 MAD 剔除时间维离群值，再求均值 | **0.88 mm** ✓ |

所以默认是 `trimmed_mean`。两个实现细节都不是可选的：

1. **离群尺度必须以一个量化台阶兜底，而不是它的 RMS。** 量化数据未充分抖动时逐像素
   MAD 会退化为 0；若用 `trim_k × 0 = 0` 作门限，`trimmed_mean` 会**静默退化成裸均值**，
   而它看起来仍然在工作。但兜底值取 `q/√12 = 0.289` 又会让 `3 × 0.289 = 0.87`
   小于一个台阶，把跨越到相邻整数的**抖动样本**（偏差 1.0）也当离群值剔掉——
   丢掉的正是突破量化的机制，结果退回台阶。取 `scale ≥ q` 则 `limit ≈ 3q`，两者兼顾。
2. **噪声底不得低于 `q/√(12N)`。** 否则单帧的稳健 sigma 会退化成 `3.7e-12`
   （lstsq 的浮点残项），把"什么都没测到"报成"极准"。低于该下限时报告下限并给出告警。

**崩溃点**：50% 帧被污染时 `trimmed_mean` 也会失效（MAD 的 50% 崩溃点）。这是
正常行为，不是实现缺陷——测试里显式记录了这一条，避免被误读。

## 领域词汇

本调研引入 `风团（wheal）`、`隆起量`、`高度残差`、`基准面`、`飞点`、`工作距离`。

注意 **隆起量**与 **高度残差** 不是同义词：前者是风团的物理高度（由后者分布导出的标量
指标，如 `peak_height_mm`），后者是逐像素的差值场。仓库尚无 `CONTEXT.md`，
待结论落定后通过 `/domain-modeling` 沉淀。

## 已知未完成

- **行的确定性伪影未定论**（优先级最高）。现有证据指向驱动 / S2D 标定而非硬件，
  但“对着平墙”那个定性实验还没做。详见上面的“未解决：上半幅的确定性行相关伪影”。
  **在这条结论落定前，上半幅（行 0–300）的深度不要用于任何测量。** 它目前也
  造成了累积降噪达不到 1/√N。
- **仓库里还没有真实录制的 fixture。** `tests/` 的序列 fixture 目前由
  `write_sequence` 合成，因为开发机上没有相机。现在已经有了真实的
  `output/seq_indoor`，但它在 `.gitignore` 里（`/output/*`），没有进版本库。
  要让 Seam 2 覆盖真实采集产物（真实的空洞与飞点分布），需要挑几帧提交进去
  或另存一份小 fixture。
- **物理校验没有做。** 合成数据测试只能证明算法没写错，证明不了测量是真的。
  需要用千分尺独立测量过的已知高度参照物（塞尺 / 垫片 / 打印仿体）做外部校验。
  这是唯一能证明结论有效的环节，见 issue #1 的 "Testing Decisions"。
- **内参未标定。** 目前用出厂近似值（`fx=fy=570.3`，HFOV 58.6°，与标称 58.4° 吻合）。
  做面积/体积之前需要真正的棋盘格标定。
